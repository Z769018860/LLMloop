# v0.97 报告 / Report (中文 / English) — 强化 LLM(提议原子 + Houdini + 反馈修复)、忠实的证书复核

## 中文
**问题与设计。** 先前的 LLM 实验要求模型给出**完整的归纳不变式**,效果差(NoOverflows:4 个模型每个只证出十几个程序)。新方案(Study HY,协议冻结在前):(1) **提示词**:声明性质只是"无未定义行为(有符号溢出、除零、移位)"、没有断言要证;解释 `NAME__in` 是入口值副本、局部变量 `NAME` 被修改;允许多循环;要求 20–30 个**多样化的原子**(循环守卫界、类型界、与入口值的线性等式、终止性相关的多项式关系、内层循环重置值),不要求归纳;(2) LLM 的原子经**采样过滤**(必须在该循环头的所有采样状态上成立)后加入 Houdini 原子池,**由 Houdini 与未改动的验证器弱化/验证**(`houdini_loops(extra_atoms=...)`,不受信);(3) **回溯修复**:卡住时(仅对预期无溢出的程序),把卡住的义务和还存活的原子发回模型,最多 2 轮,新原子合并后重跑;预期有溢出的程序只做第 0 轮(对照)。你提到的三个翻译问题(入口值丢失、局部变量被拒、断言变义务)在 v0.93–v0.96 已在翻译器中修复,本轮提示词与之对齐。
**结果(67 个预期无溢出 + 106 个预期有溢出,翻译 v096;注意该集合已用于开发,这是开发后数字)。** 692 次运行(4 个模型 × 173 个程序):预期有溢出的程序 **0 次被认证**(424 次运行);预期无溢出:**至少一个模型证出 57/67**,各模型单独 52–57(旧的纯 LLM 方案:45/67 至少一个模型,各模型单独仅十几个)。并上无 LLM 流水线:**59/67,Ultimate 56**,我们独有 6、Ultimate 独有 3(`parity`、`nestedLoop-1`、`Benghazi`)。
**如实的归因。** (a) **修复轮几乎没起作用**:213 个证明中 210 个在第 0 轮完成,仅 3 个靠修复轮——"回溯采样"的收益很小,不应当宣称为贡献;(b) 提升的主要来源是"LLM 只提原子、Houdini 做验证/弱化"这一改法,以及翻译修复;不含 LLM 额外原子的默认 Houdini 为 53,混合方案各模型 52–57,LLM 的净增量约 0–4 个程序(并集上多 4 个)。**这不是"LLM 很强",而是"LLM 提供了少量有用的原子,系统主要靠生成器 + 验证器"。**
**证书独立复核(CBMC 循环契约)——含一个重要的复核脚手架更正。** 复核器曾把 Python 语义的不变式语言近似翻译成 C(链式比较、`%`、`//`、常量宽度),产生了假的 FAILED(先后 6 个,每个都查明是脚手架问题:链式比较 `x - 1 < x <= y`、`4*z % m` 的优先级、`2*2147483647` 的 int 溢出)。现已改为基于 Python 语法树的忠实翻译,并**用它重跑全部旧复核**:Study HY 190 个证书 **155 VERIFIED、0 FAILED**(26 转换错误、9 超时),57 个被证明程序中 45 个至少有一个被 CBMC 验证的证书;v0.93/v0.94/v0.96 的 NoOverflows 复核分别为 113/119、137/155、80/102 通过、**0 FAILED**;更早的 241 个证书为 239 通过,2 个 FAILED 恰为审计找出的失效旧证书。
**局限。** 提示词/方案是在已用于开发的集合上设计的;单次采样温度 0.7;4 个模型;多循环程序的复核只对第一个循环施加契约(其余由 CBMC 展开,VERIFIED 有效而 TIMEOUT/ERROR 无结论);对 Ultimate 未做见证复核;性质与 no-overflow 并不完全相同(我们还检查除零等)。
## English
**Problem and design.** Earlier LLM studies asked for a complete inductive invariant and did poorly (4 models proved only a dozen programs each). New design (Study HY, protocol frozen first): (1) prompt: the property is only "no undefined behaviour (signed overflow, division by zero, shifts)", no assertion to prove; `NAME__in` is the entry copy, the local `NAME` is modified; several loops allowed; asks for 20–30 **diverse atoms** (guard bounds, type bounds, linear equalities with entry values, termination-style polynomial relations, reset values of inner loops), not inductive; (2) the atoms are filtered against the sampled states of each loop head and added to Houdini's pool; **Houdini and the unchanged verifier do the weakening/proof** (`houdini_loops(extra_atoms=...)`, untrusted); (3) **backtracking repair**: when stuck (only for programs expected overflow-free) the stuck obligation and surviving atoms go back to the model, up to 2 rounds; overflowing programs get round 0 only (controls). The three translation problems you listed were already fixed in v0.93–v0.96; the prompt is aligned with them.
**Results (67 overflow-free + 106 overflowing; translation v096; the set was used for development, so post-development numbers).** 692 runs: **0 of 424 runs on overflowing programs certified**; **57/67 programs proved by at least one model**, 52–57 per model (old pure-LLM: 45/67 by any model, a dozen per model). With the LLM-free pipeline: **59/67 vs Ultimate 56**; ours-only 6, Ultimate-only 3 (`parity`, `nestedLoop-1`, `Benghazi`).
**Honest attribution.** (a) **The repair rounds barely mattered**: 210 of 213 proofs were found in round 0, only 3 needed repair — "backtracking sampling" is not a contribution; (b) the gain comes mostly from "LLM proposes atoms, Houdini + verifier do the proof" and the translation fixes: default Houdini 53, hybrid 52–57 per model, net LLM contribution ≈ 0–4 programs (+4 in the union). **This is not "the LLM is strong"; it is "the LLM adds a few useful atoms; the system relies on the generator + verifier".**
**Independent re-check (CBMC) — with an important harness correction.** The re-check harness approximated the Python-syntax invariant language in C (chained comparisons, `%`, `//`, constant widths) and produced spurious FAILED results (6 at first, every one traced to the harness: chained `x - 1 < x <= y`, precedence of `4*z % m`, int overflow in `2*2147483647`). It now uses a faithful Python-AST translation and **all old re-checks were re-run**: Study HY 190 certificates **155 VERIFIED, 0 FAILED** (26 conversion errors, 9 timeouts), 45 of the 57 proved programs have at least one CBMC-verified certificate; NoOverflows re-checks 113/119, 137/155, 80/102 verified, **0 FAILED**; the earlier 241 certificates: 239 verified, the 2 FAILED are exactly the stale certificates found by the audit.
**Limits.** Prompt and design were developed on a set already used for development; single sample at temperature 0.7; 4 models; multi-loop re-checks apply a contract to the first loop only (VERIFIED is valid, TIMEOUT/ERROR inconclusive); no witness validation of Ultimate; our property (also division by zero etc.) is stricter than no-overflow.
