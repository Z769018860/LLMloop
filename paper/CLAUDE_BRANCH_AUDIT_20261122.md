## 3. 本轮发现并处理的修正

### 3.1 证书截断去重遗漏：已修代码，补验有未决项

`cert_recheck_flat_run_v100.py` 用 `(program, json.dumps(invariant)[:600])` 去重。实际数据中，`GCD2.c` 和 `NO_04.c` 各有两份不同证书共享同一前缀，旧调度器各遗漏一份。

四个复核批次内各自去重后应为 117、179、102、190，合计 **588 项**；旧调度得到 117、177、102、190，合计 **586 项**。这是批次内计数之和，不是全局独立程序数。原来的 556 VERIFIED、29 TIMEOUT、1 ERROR 仍是确实存在的 **586 条被选取记录**，不能写成所有不同证书均已覆盖。

已改为完整规范化 JSON 作为证书身份，保留全部原子及循环顺序。三项实际历史数据回归测试通过。对遗漏两份证书使用当前 CBMC 6.11.0 作独立补验：

| 遗漏证书 | 本轮补验 | 条件 |
|---|---|---|
| GCD2，完整不变式哈希 `22be620f…` | VERIFIED | LP64，保留断言、算术与除零检查 |
| NO_04，完整不变式哈希 `e602092a…` | TIMEOUT | 相同检查，30 秒宿主时限 |

具体源码、请求、完整输出和二进制/驱动哈希见 [补验记录](../experiments/claude_paper_audit_20261122/omitted_certificates/results.json)。为适配 CBMC 6.11 的无函数体检查，辅助输入使用显式 typed havoc；未关闭任何原有断言。该补验不是重跑历史 586 条，不将异环境结果拼成一次统一复验。独立复核器仍是我们对证明规则的再实现，且会过滤部分原子；应记录过滤清单与语法映射，不把它称为验证了证明规则本身。

### 3.2 主稿的性质等价表述：已修

“断言失败转换为除零”不意味着“整个译写程序无 UB ⇔ 断言成立”。例如前序 `INT_MAX+1` 已有 UB，即使最终断言恒真也不能证明整个程序有定义。主稿已改为：无 UB 还要求前序运算有定义；数学整数、typed C 与 NoOverflows 研究分列，并说明 NoOverflows 移除断言义务。

### 3.3 主稿计数和比较措辞：已修

已给摘要和 §4d 增加 165/93/72、单目录、unknown 标签及预算限制，区分证明和判定配对。主稿中 v0.91 的 238/241 已按当前数据修正为 **239 VERIFIED、2 FAILED**。删除了由旧实验未验证见证就推断 CPAchecker 不支持独立证书的措辞。论文 README 已指向当前双语主稿，旧 `draft.md` 标为早期轨迹加速稿，避免两条主线混读。

### 3.4 Claude 分支的合成 oracle 仍有已确认缺陷

直接调用 Claude 原生成器可复现：循环 guard 的 nondet=1、body 的另一调用=0 能到达 `INT_MAX+1`，原 oracle 因共享选择却报告 SAFE。包含 `&& nd` 的 guard 还会因替换 `and` 中的 `nd` 而发生 SyntaxError。这与 PR #31 的修复一致。Claude 的历史 60 个合成标签目前不能作为可靠真值证据；应合入修复并保留旧标签失效说明，再开展新实验。本轮不把该缺陷误写为核心验证器误认证。

## 5. LLM 证据的具体问题

新集合 372 行、开发研究 692 行，共 1064 条结果记录缺少 usage/tokens/latency 字段。`call_provider` 返回响应、重试与请求体，但这两个 hybrid 驱动只持久化原子、状态和简化轮次，不保存完整响应或调用延迟。因此现有文件不能验证端到端成本、费用或历史重试总成本，不能用零/估算值补齐。

对新集合，四个端点别名的证明数为 90、88、88、84；相对非 LLM 并集 88，所有端点合计新增的是 **三个程序**：`McCarthyIterative`、`ex3a`、`java_Sequence`。不能把“每模型 52–57”当作全部由模型新增的能力，也不能把多模型并集当作一次调用的结果。

修复轮在驱动中根据已知 expected 标签决定是否执行：true/unknown 可修复两轮，false 仅首轮。这可以作为明确标注的控制实验，但不是标签盲的部署策略。前瞻性评估应在所有程序上使用一致的、只依赖验证器反馈的有界策略；至少分别报告 round-0、修复及总预算。端点名 `claude-dsflash-itkk` 在项目中已说明是 DeepSeek 别名，不能据名称宣称测试了 Claude 架构。

## 6. 写作方向与当前可成立的主张

建议收敛为四个问题：RQ1 在声明语义与契约下，证书/见证有何可独立检查的可靠性证据；RQ2 在包含不支持项的总体上，覆盖、证明与证伪能力如何；RQ3 LLM 相对确定性候选究竟额外解决什么、花多少成本；RQ4 哪些组件有效、何时失败及如何随规模变化。

目前可写：“在一个前端接收的 93 程序子集上观察到更多证明；负例控制中未观察到误认证；一部分证书由独立引擎复核，正见证可重放；泛化受前端、语义、候选与求解预算限制。”

目前不能写：“全面优于现有最好工具”“零误认证保证”“每个结果都已经独立验证”“所有 UB 均覆盖”“完整 C/通用堆分析”“LLM 已具有可验证的端到端成本优势”。相对既有提案—验证工作的方法新意仍需单独论证；有大量工程功能或 p<0.05 不能替代方法贡献与外部效度。
