# LLMloop 实验与实现完成报告

2026 年 11 月 6 日

## 完成结论

本轮完成了 typed 源码轨迹的多候选认证与显式有界回退，并修复了原有除法归纳证明中造成超时的一类宽位向量乘法编码。冻结源码的完整回归通过 **3,212 项测试，0 失败，0 跳过**，比 v0.58 增加 51 项，未删除原有测试。配对试验覆盖 7 个不同源码程序的 13 种配置，其中 7 种获得轨迹证书、1 种通过完整退出的有界回退、5 种保持 UNKNOWN。全部结果来自本地执行，没有使用 GitHub Actions 或 KLEE。

项目现阶段可以形成一份完整研究论文草稿。现有证据支持受限语义下的方法、实现和组件正确性讨论，尚未支持真实 LLM 增益、对外部工具的优势或普遍分析加速比。报告把这些研究证据缺口与通用 C 功能缺口分别说明，便于后续工作聚焦论文主张。

## 研究目标与已具备能力

论文沿用原研究方向 LLM-Guided Certified Loop Acceleration via Periodic Invariants and Compositional State Summaries。目标是给出经过独立检查的精确状态轨迹，使周期状态和单调状态共同演化，并在每一次真实入口处组合嵌套循环。模型或其他生成器只提出候选；独立验证器决定候选是否可用。

已有数学路径与 SCC、选定周期调度、矩阵及多项式闭包、受限自动候选和 typed 轨迹模块。源码验证固定 ABI、输入域和整数语义，对初始化、循环条件、中间运算、后继状态、退出和返回分别建立义务。嵌套摘要绑定当前调用的实际入口状态。有限数组、VLA、有限对象调用和特定拥有链表也有各自独立的支持契约，不能据此声称任意 C 或任意堆已经完成。

内存访问代价和概率分析属于后续扩展，不作为当前论文的核心贡献。精确循环次数也不等于任意内存访问代价。

## 本轮完成的功能

### 多候选轨迹认证

新增 `typed_summary_portfolio` 前端，接受 1 至 8 个带唯一 id 的不可信候选，后端固定为 typed recurrence 或 typed nested。协调器在求解前检查全部候选的结构，包括最终可能不执行的后缀；候选不能覆盖源程序、输入域、ABI、证明预算或成功标记。每次尝试均在同一个原始上下文的深拷贝上使用新的既有验证器。

选择规则是按给定顺序保留第一个通过完整检查的候选。仅当后端返回精确的成功状态，且源码定义性和终止性标记均为真时才接受。记录保留失败候选、已选择项、未尝试项、上下文与源码哈希及时间。候选失败只表示未能认证该候选，不自动构成源码存在可达未定义行为的证明。

### 显式有界回退

所有候选均未获认证时，可在同一源码、域和 ABI 下启用 1 至 512 步的原始 typed CFG 回退。回退必须证明完整退出；其结果继续保留原始有界证明状态，不能标为加速摘要。候选和回退均失败时返回 UNKNOWN，不收缩输入域以制造成功。

每个证明查询仍采用原有时限。最多 8 次独立认证再加回退可能明显超过单个查询的 5 秒预算；当前入口并不提供 5 秒总截止保证，也不声称候选顺序具有最优代价。

### 除法证明编码修复

诊断在原有除法归纳测试中保留了单查询 timeout 记录。修复在每一个源步骤查询中保留实际余数与期望余数、实际进位与期望标志的对应等式，再依据同余性将守恒式中的宽乘法改写为 Boolean 条件形式。两种 Boolean 分支均通过符号恒等审计，原始中间运算的定义性谓词继续参与同一个证明目标。

直接与包装形式仍分别执行原有 39 和 40 个查询，单查询 5,000 毫秒、函数证明 30,000 毫秒的预算没有提高。新增测试检查全部 31 个步骤均保留对应等式，并以删除进位对应等式可产生反例的控制检验该审计。定向测试共 102 项通过，其中候选协调 49 项、归一化审计 2 项、原有除法测试 51 项。

## 验证方法与结果

### 冻结与完整回归

本轮实际执行的本地提交为 `286039d37395a1b4517cc1b1390daf992c6dfe20`，源码树为 `0abb381eef8942517e97a36519749068384bd3c8`；对应 GitHub 源码提交为 `2806c4668c4265c6a1be2c7e20ae4228bd304f6b`，两者源码树相同。验证前冻结的 450 个源码、测试、配置和论文相关路径，以及 595 个历史证据路径，均在结束时重新核对哈希。

完整回归先收集 3,212 个唯一测试项，再按完整文件划入两个互不重叠的分组。每项使用独立 fork，保留 setup、call 和 teardown 事件；接受条件要求两组退出码均为零、收集并集完整、每项恰好执行一次且全部通过。总截止为 1,800 秒，本次完整回归耗时约 528.8 秒。该耗时用于复现记录，不作为通用性能增益。

| --- | --- | --- |
| 完整测试 | 全部 3,212 个测试项 | 3,212 通过 无失败或跳过 |
| 新增测试 | 49 候选协调和 2 归一化审计 | 51 项全部通过 |

13 种配置不是 13 个独立程序，92 次原生执行也不是 92 个被普遍证明的程序。原生网格使用小规模和边界输入；十亿或万亿次数的结果来自符号轨迹证书，没有通过实际执行相应次数获得。

配对基线固定为同域、同 ABI 的 128 步原始 bounded CFG。每种模式使用新 Python 工作进程，分别记录包含进程启动的墙钟时间和分析内部时间。试验只评价协调机制在预先给定候选下的行为，没有测量模型生成延迟或真实模型准确率；单次、手工构造配置不能推出普遍加速比。

### 失败与中断记录

早期 sequential 完整回归出现原有除法测试失败后中断，两个隔离检查在相同时限内通过；当时未恢复完整断言栈。随后双分组完整尝试也因原有除法 UNKNOWN 失败而中断。进一步的专门诊断记录为旧除法测试 45 项通过、6 项失败，并明确捕获查询超时，才实施上述源义务不变的等价改写。

修复后的第一次冻结完整运行因执行环境结束而中断，保留的部分逐项记录没有失败事件，但没有完成结果，因此不计为验收通过。本次另行从完整收集开始，得到独立的完整通过记录。共启动四次完整回归，其中三次未完成，一次完成；这些记录保留在同一原始证据归档，不能只呈现最终成功运行。

最早原生控制假设所有抵消中间溢出执行都会触发 UBSan，实际不成立。现已把这些观测与正例输出、要求 trap 的可观察危险控制分开。`(x + 1) - 1` 的有符号中间溢出在源码层面仍须拒绝，sanitizer 沉默不能证明源执行有定义。此前失败脚本、日志和部分原始结果同样保留。

## 尚未覆盖的通用功能

任意耦合、状态分支递推的闭式自动发现，以及任意 C 的终止性不能由当前受限方法保证。通用多对象堆、别名、形状归纳、递归堆、任意跨过程修改和所有权契约仍未完整实现。浮点、一般 union、字节内存与 effective types、函数指针、变参、外部库、并发和更广 VLA 布局也有未覆盖范围。Clang 连接或导出 LLVM IR 不等于建立这些语义。

typed 提案入口目前接收外部给定候选；稳健的真实模型到 typed 轨迹流水线、全流程总预算和经过实测的候选选择策略仍有待完善。当前已有数学 cycle 和 invariant 的可选远程接口，不能据此声称 typed 轨迹真实模型试验已经完成。KLEE 按项目约束不集成，不列为强制缺口。

这些通用功能无需全部做完才撰写受限范围的论文。下一阶段应先固定基准和共同任务，再接入有完整来源记录的模型试验，并运行外部对照、消融和重复计时。遇到未建模源码继续返回保守结果，避免用收窄输入域或删除失败行扩大成功率。
