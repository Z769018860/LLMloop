# v0.85 报告 / Report (中文 + English)

## 1. 语句表达式（GNU `({ ... })`）
文本层改写（`rewrite_stmt_exprs`）：把语句表达式提到所在语句之前的块里，最后一个表达式赋给新变量，变量类型取**体内第一个局部变量的类型**（MAX/MIN/SWAP 宏的形状）；循环头里的语句表达式、没有类型化局部变量的形状被拒绝。用 `MAX2` 宏函数验证：本机差分一致。真实库代码里没有出现需要它的认证函数。
## 2. 越界检查扩展（`scripts/memsafe.py`）
- **嵌套结构体与数组字段**：访问路径 `p->f`、`p[i].f`、`(*p).f` 之后可接任意 `.g` / `[k]` 链；数组字段按**声明的维度**检查下标；指针字段/结构体值字段只检查根元素，值留给内存抽象（计入"未检查"）。
- **`char**`**：指针元素基对象，`argv[i]` 的下标被检查，`argv[i][j]` 的内层访问**没有大小信息**（计入未检查）。
- **堆对象来源追踪**：`p = malloc(n)` / `calloc` / gnulib 的 `xmalloc/xzalloc/ximalloc/xcalloc/xnmalloc`：每个分配点是一个基对象，记录大小（按元素）、可能为 NULL（`malloc` 可能失败，`x*` 不会）、已释放标志；`p = NULL`、`if (p == NULL)`、`free(p)` 被理解；堆对象**不需要调用者契约**。未判空就解引用 `malloc` 的结果、`n+1` 溢出、释放后使用都不会被证明。
- **不同指针参数之间的重叠**：`memcpy(d, s, n)` 对两个不同的指针参数需要"互不重叠"：引入每个参数的位置变量 `<b>__pos`，契约原子 `pos_d + n_d <= pos_s || pos_s + n_s <= pos_d`（"disjoint objects"）；没有这个契约的 `memcpy` 不被证明。AddressSanitizer 验证：丢弃该契约后在重叠输入上 ASan 报 17/60 个错误，保留契约时 0 个。
- **被调函数内部的访问（同文件函数）**：先对被调函数做越界检查并得到契约（一层深、带缓存），调用点把契约按实参实例化（指针参数的 `p__n` ← 剩余元素数 `size − offset`，`p__null` ← 基对象的空指针变量，整数参数 ← 实参表达式）作为**检查式**；被调函数无契约即安全时直接计为已覆盖；传入未跟踪指针时无法检查（计入未检查）。
- **ASan 交叉验证（37 个合成函数）**：被证明的在满足契约的精确大小缓冲区上 ASan **0 错误**；缺陷版本（堆溢出、堆 use-after-free、`argv` 越界、字段数组越界、被调函数调用点越界、memcpy 重叠…）**没有**被证明，其中 ASan 能确认的全部报错；**证明了但 ASan 报错：0**。`heap_unchecked_null`（`malloc` 失败时解引用）不被证明，但 ASan 不能确认（malloc 不会失败）。
- **全量覆盖（1044 个已认证的含循环函数，上一版 39/1043）**：`PROVED_MEMSAFE` **117**（检查 278 处访问、12 处库函数区间/释放检查、11 处被调函数契约检查），`NOT_PROVED` 70，`NO_CHECKED_ACCESSES` 45，`NOT_APPLICABLE` 812（无可跟踪指针 352、跟踪指针被当作值 185、含未跟踪指针表达式 173…）。**注意**：117 个里 104 个契约是"非空 + len ≥ 1"（结构体指针在偏移 0 处解引用及其指针字段的根检查），所以数字大幅上升主要来自把结构体/嵌套字段/`void*` 纳入跟踪，不是缓冲区索引证明变多。9 个跟踪到堆对象的真实函数**没有一个被证明**。
## 3. goto：跳入块
前向 `goto` 到后面某个 `if` 的分支里的标签：挂起跳转变量；`if` 的条件变成 `cond || 跳转挂起`，分支里标签之前的语句在跳转进入时被跳过，标签处清除标志。本机差分（80 例，覆盖两种进入方式）一致。未消除的 goto/标签从 16 降到 **11**（跳入循环/`switch`、跳入 `else` 分支等仍拒绝）。
## 4. 给"即使有假设也不能认证"的函数补前置条件（`scripts/assume_infer.py`）
新增**参数前置条件**维度：`nonzero | pos | small` 作用于所有整数参数，再叠加读值假设，两者都用 delta-debugging 最小化；读值与参数的关系型夹取 `le:q`（`v <= q`）放在最后尝试（避免"让循环不执行"这种退化假设）。对此前 50 个"即使有假设也不能认证"的函数：**再认证 2 个**（例如 `hash_string`：`tablesize != 0`；`list_entries_users`：`n_in > 0`），4 个超时，44 个仍不能。92 个函数合计：**18** 个在最小假设下认证。其余 44 个的原因不是单个读值或参数前置条件（例如需要循环不变式、多个读值之间的关系、或抽象本身的误报），我没有给出更具体的关系型前置条件。
