# v0.92 报告 / Report (中文 / English) — 针对"弱于其他工具"的修正与实验

## 中文
**结论先行:修正显著提升了我们在多项式/幂和程序上的能力,但证据仍然不支持"优于现有最好工具"。**
**1. 工具链修正(均为不受信的生成器侧改动,验证器与其求解配置未改;默认关闭,冻结流程不变)。** `houdini_loops(poly=True)`:(a) 从样本挖次数 ≤5 的多项式等式(列去重、排除标志位);(b) 按退出标志条件化的关系和条件多项式等式(解决 `break` 退出状态缺少 `n>a` 之类关系导致出口义务失败);(c) 精简原子集(去掉模数/无条件值集噪声,否则非线性查询变难)。定位过程:`cohencu` 的出口义务失败并非求解器能力问题,而是不变式缺少"退出时才成立"的条件关系;补上后被未改动验证器认证。"按参数符号条件化"的原子在开发集上使结果更差,默认关闭(`SIGN_COND=False`)。
**2. 结果(unsafe 对照在所有配置下 0 次被认证)。**
- 留出集 A(`nla-digbench`+`loops-crafted-1`,冻结 29 个可判定程序、22 个预期成立):默认 Houdini 2 → 多项式配置(数学模型)5(C 模型 2);LLM(Study HO)8;我方并集 **12**,对比 Ultimate 8、CPAchecker 5、ESBMC 1;5 个程序仅我们证明。**注意:** 多项式配置的开发就用了这个集合里的 `cohencu`/`ps3`,所以对该配置它**不再是留出集**;只有 LLM 的 8 个仍是留出结果。
- 新集 B(`nla-digbench-scaling`+`bitvector-loops`,63 个预期成立程序,同族不同常数/展开界,**不是族不相交**):默认 Houdini 13 → 多项式配置 **46**(数学模型;C 模型 40);LLM(4 个模型、1 次采样,200 个响应)21 个程序(全部已被多项式 Houdini 覆盖);工具:**CPAchecker 63/63、ESBMC 45、Ultimate 34**。**我们独有 0 个,CPAchecker 明显强于我们。** 这些 `valuebound`/`unwindbound` 变体对有界模型检查很友好。
- 多项式配置在开发/测试之间的稳定性:同一代码在 v0.91 留出集上数学模型得到 10–12/42(受机器负载与 20 s 求解超时影响;一次运行因遗留 z3 进程抢占 CPU 而偏低,已清理后重跑得 11),在 scaling 集两次得到 46。
**3. 判断。** 在**不同性质**的比较里:我们证明"无未定义行为 + 断言"(C 模型)或断言(数学模型),并可由 CBMC 独立复核;工具检查回绕语义下的断言可达性。在小而难的多项式集合 A 上我们的并集最好(12 对 8),在大而易于有界展开的集合 B 上 CPAchecker 全胜。因此:**可以主张"互补"(5 个程序仅我们证明;在多项式幂和族上能力大幅提升),不能主张"总体优于最好工具"。**
**4. 仍存在的局限(未解决)。** `ps4–ps6`(次数 ≥4 的幂和)、`hard`/`divbin`(含除法的二进制循环)仍未认证,多卡在出口义务或循环体内断言;`gemini-3-flash` 不可用,`glm-5.3-ark` 在 Study HO2 中只有 2 个响应(传输失败),所以 HO2 只有 4 个模型;C 模型下多项式程序提升较小(位向量非线性)。
## English
**Bottom line: the fixes substantially improve us on polynomial/power-sum programs, but the evidence still does not support "better than the best existing tool".**
**1. Toolchain fixes (untrusted generator side only; verifier and its solver settings unchanged; off by default so the frozen pipeline is unaffected).** `houdini_loops(poly=True)`: (a) polynomial equalities up to degree 5 mined from samples (column dedupe, flags excluded); (b) flag-conditioned relations and conditional polynomial equalities (the exit obligation failed because the invariant lacked relations that hold only at the `break` state, e.g. `n > a`; it was not a solver-power problem); (c) a lean atom set (moduli / unconditional value-set noise makes nonlinear queries harder). Sign-conditioned parameter atoms made the development result worse and are off (`SIGN_COND=False`).
**2. Results (unsafe controls never certified in any configuration).**
- Held-out A (`nla-digbench` + `loops-crafted-1`, 29 decidable, 22 valid): default Houdini 2 → polynomial profile 5 (C model 2); LLM (Study HO) 8; our union **12** vs Ultimate 8, CPAchecker 5, ESBMC 1; 5 programs proved only by us. **Caveat:** the polynomial profile was developed on `cohencu`/`ps3` from this very set, so A is no longer held-out for it; only the LLM's 8 are held-out.
- New set B (`nla-digbench-scaling` + `bitvector-loops`, 63 valid, same families with other constants/unwind bounds, **not family-disjoint**): default Houdini 13 → polynomial profile **46** (math; C model 40); LLM (4 models, 1 sample, 200 responses) 21 programs (all already covered by polynomial Houdini); tools: **CPAchecker 63/63, ESBMC 45, Ultimate 34**. **We have 0 programs of our own; CPAchecker is clearly stronger.** These bounded `valuebound`/`unwindbound` variants suit bounded model checking.
- Stability: the same code gives 10–12/42 on the v0.91 held-out set in the math model (machine load and the 20 s solver timeout matter; one run was depressed by orphaned z3 processes — cleaned and re-run: 11); 46 on the scaling set in two runs.
**3. Judgement.** The properties differ (we prove UB-freedom + assertion in the C model, or the assertion in the math model, with CBMC-checkable certificates; tools check assertion reachability under wrap-around). On the small hard polynomial set A our union is best (12 vs 8); on the large bounded-unrolling-friendly set B CPAchecker wins outright. So: **"complementary" is supportable (5 programs proved only by us; large gains on polynomial power-sum families); "better than the best tool overall" is not.**
**4. Remaining limits.** `ps4–ps6`, `hard`, `divbin` still uncertified (exit obligation or in-loop assertion); `gemini-3-flash` unavailable and `glm-5.3-ark` returned only 2 responses in Study HO2 (4 models); smaller gains in the C model for polynomial programs (nonlinear bit-vectors).
