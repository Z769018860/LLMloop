# v0.84 报告 / Report (中文 + English)

## 1. 空指针 / 释放后使用 / 重叠 / 库函数内部访问 / `void*` / 结构体指针（`scripts/memsafe.py`）
- **空指针**：每个被跟踪的指针参数多一个 `p__null`（0/1）。访问要求"不为空"进入检查式；`q == NULL`、`!q`、`if (q)` 被理解成对 `p__null` 的测试（所以显式判空的函数不需要"非空"契约）。契约阶梯：无 → 非空 → 长度契约 → 非空+长度契约。
- **释放后使用 / 重复释放**：被 `free` 的指针参数有 `p__fr` 标志；之后的访问和再次 `free` 被检查（`free(NULL)` 合法，偏移必须为 0）。
- **库函数内部访问**：对被跟踪指针调用 `memcpy/memmove/memcmp/memset/strncpy/strcpy/free` 时，被访问的**区间**被检查（`strcpy` 用字符串长度），`memcpy` 还检查同一基对象上的**重叠**；不同指针参数默认互不重叠（写入契约说明）。
- **`void*`**：只被转成字节指针的 `void*` 参数当作字节缓冲区（元素 `unsigned char`）。
- **结构体指针/数组**：`p->f`、`p[i].f`、`(*p).f` 对结构体元素基对象检查（元素大小按元素计，字段读取返回字段类型的任意值；字段类型来自结构体定义）。`p->arr[i]` 的内层数组访问、`char**`、嵌套结构体链**没有**检查。
- **用 AddressSanitizer 验证（24 个合成函数，其中 12 个安全/12 个有缺陷或契约敏感）**：被证明的函数在满足契约的精确大小缓冲区上运行 ASan **0 错误**（空指针对判空函数 30% 的试验中真的传了 NULL）；use-after-free、double-free、memcpy 重叠、`void*` 与结构体数组越界等缺陷版本**没有**被证明且 ASan 全部报错；**证明了但 ASan 报错：0**。已知的契约遮蔽：`memcpy(d, s, n+1)` 只在契约 `len >= n+1` 下被证明（这是一个真实的调用者要求，已标注）。
- **全量覆盖（gnulib+coreutils 的 1043 个已认证含循环函数）**：`PROVED_MEMSAFE` **39**（上一版 14；检查 63 处访问、3 处库函数区间检查；契约：非空+len≥1 共 28、非空+len≥整数参数 6、无 4、非空 1），`NOT_PROVED` 35，`NO_CHECKED_ACCESSES` 83，`NOT_APPLICABLE` 886（无可跟踪指针 371、跟踪指针被当作值 164、含未跟踪指针表达式 163、结构体字段类型未知/非标量 113…）。**注意**：28 个"非空+len≥1"主要是结构体指针在偏移 0 处解引用，`len ≥ 1` 对结构体指针是自然契约；真正的缓冲区索引证明只有少数。堆对象（malloc 结果）、`char**`、被调函数（库函数之外）的内部访问仍未检查。

## 2. goto / asm / 语句表达式
- **goto**：现在按**语句列表**处理（任意嵌套层，内层优先）：**后向 goto** → `while (1) { 区域; break; }`，`goto L` → `continue`；**前向 goto** → 每个列表一个挂起跳转变量，后续语句与含 goto 的循环条件加保护；嵌套标签、循环体内的 `continue` 式标签都支持。用 38 个函数验证，4 个新的合成函数（后向重试、嵌套标签、转发出口、清理链）本机差分一致。仍被拒绝的 goto/标签 16 个（跳入块、`for/switch` 内的跳出等；之前是 88 个）。
- **asm**：`asm(...)` 变成 `__asm_havoc(&输出1, ...)`：输出操作数被覆盖为任意值（有类型），屏障型 asm 无输出；输入操作数被忽略。
- **语句表达式 `({ ... })`：没有做**（真实代码里只有零星几个函数，pycparser 不支持，也没有安全的文本改写）。

## 3. 给"可能有算术未定义行为"的函数补前置条件（`scripts/assume_infer.py`）
对每个因内存抽象而卡在"操作有定义"的函数（按源码文本去重，92 个），把"通过指针读到的值"上的假设实现为**读值的夹取**（`t = nondet_T(); if (!P(t)) t = safe;`），从弱到强尝试 `nonzero | nonneg | divisor(≠0 且 ≠-1) | small(|v|≤2^15) | nonzero+small`，找到能认证的最弱模板后用 delta-debugging **逐个释放读点**，得到**最小的读点集合**和它们所在的语句。
| 结果 | 个数 |
|---|---|
| 在最小假设下认证（`small` 12、`nonneg` 2、`nonzero+small` 1、`nonzero` 1）| **16**（例如 AVL 树的 `node->height + 1`：假设高度远小于 INT_MAX）|
| 即使在所有读点上做这些假设也不能认证 | 50 |
| 没有读点（算术本身可能未定义，或来自别处）| 16 |
| 读点太多（>10）| 9 |
| 出错 | 1 |
**说明**：认证结果是"在这些读值假设下无算术未定义行为"，假设是**对调用者/数据的要求**，不是证明；50 个没有被这些模板救回的函数需要更具体的关系（读值之间/与参数之间）。
