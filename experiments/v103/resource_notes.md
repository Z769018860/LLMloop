# Resource interpretation

Every command has a 600 s wall limit / 2 GiB sampled process-group RSS limit in the full-165 study; the external-label study declares its separate 60 s / 512 MiB limits. All tools in one study receive the same outer limits, including startup. Ultimate's JVM heap is additionally fixed at 1 GiB; the release's default and fallback logical configurations are retained. A tool may return UNKNOWN early under its frozen algorithm (e.g. CBMC unwind64). Equal outer caps do not mean every algorithm exhausts its budget or proves exactly the same set of obligations.

Process groups are owned and killed on timeout or sampled memory excess. The sampler writes live-group RSS and live-process CPU every 0.1 s. Summed RSS may double-count shared pages and can miss sub-interval spikes; wait4 maxrss is also preserved. CPU user/system from wait4 includes reaped descendants. On forced group termination, some orphaned descendants may not be included in the root's wait4 CPU accounting; those values are partial, and live CPU samples are not a complete lifetime sum. Reports must flag this and must not infer cross-tool CPU speedups from timeout CPU values. Successful-tree wait4 observations and every raw sample are retained. Concurrent wall times are throughput observations, not a paired speedup study.
